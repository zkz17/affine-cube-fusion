# Data layout and naming conventions

The existing random/exhaustive per-case files are **line-aligned with `test_cases/test_cases_{n}`**: line `i` of any
per-case file for a run starting at zero (line 1-based) refers to the truth table on line `i` of the test-case
file. Each per-case line has the form `tt:value`, where `tt` is the truth-table integer and
`value` the per-case number (a T or CX cost, or a lower bound).
For a run starting at `start`, output line `i` corresponds to input line `start + i`.

## Directory overview

The separate application-derived datasets are documented in
[`test_cases/structured/README.md`](test_cases/structured/README.md). Their 51
output functions retain fixed input counts: DES has 32 functions with 6 inputs;
AES has 8 functions with 8 inputs; Ascon has 5 functions with 5 inputs; SPEEDY
has 6 functions with 6 inputs. The manuscript's cryptographic S-box panel includes
all four datasets, ordered by input count: Ascon, SPEEDY, DES, and AES.
`evaluate_structured.py` writes dataset-specific CSV records to
`structured_cost/<dataset>/<method>/`, with explicit timeout/error statuses and
full-dataset means only for complete runs. These files are **not** aligned with
the random `test_cases_{n}` files and must not be mixed with their baselines.

All four datasets also have exports in the existing text formats, alongside their CSV
records under `structured_cost/<dataset>/`:

- `exorcism_cost/exorcism_{t,cx}_cost` and `exorcism_time`;
- `sshr_cost/sshr_{t,cx}_cost` and, for a complete successful group,
  `sshr_time`;
- `{F,FS,FP}/our_{t_cost,cx_cost,results}_{route}.txt`.

The dataset subdirectory is essential: even DES and SPEEDY, both at n=6, contain
different functions, and none is aligned to the random `test_cases_{n}` files. The T/CX files
retain the exact `tt:integer_cost` format, while `our_results` retains the usual
mean wall time and lower/higher/same comparison blocks. The source CSV records
remain authoritative. Regenerate/check these exports without synthesis using:

```bash
python experiments/export_structured_results.py
python experiments/export_structured_results.py --check
```

DES SSHR-H completed 32/32. AES SSHR-H attempted all 8 outputs and timed out on
all 8 at the 1200-second per-function limit. Accordingly, AES's two SSHR cost
files are empty and it has no numeric `sshr_time`; `sshr_results.txt` records
the timeout coverage. Its ACF result reports skip the SSHR cost comparisons.
No timeout is substituted with zero cost or a successful 1200-second runtime.
For Exorcism, the structured exporter writes one `total runtime` / `average
runtime` pair, using the recorded mean of the two cost-interface calls for each
output. It does not invent separate T/CX timing measurements from that mean.

```
data/
  test_cases/        test_cases_{n}: one truth-table integer per line (random sample per n)
  exorcism_cost/     exorcism_{t,cx}_cost_{n}: Exorcism baseline T/CX cost per case (n=3..11),
                     exorcism_time_{n}: Exorcism runtime per n
                     exorcism_time_{n}_0_1000.txt: matched 1000-case runtimes at n=8,9,10
                     matched_timing_20260926.txt: protocol and validation for those reruns
  sshr_cost/         sshr_{t,cx}_cost_{n}: SSHR baseline T/CX cost per case (filled n=3..6;
                     the n=7..10 files are empty), sshr_time_{n} (n=3..6)
  our_cost/
    {path}/          one folder per base route: A A0 F F0 FS FP FG MT MT0 PK PK0 PKP PKS.
                     Each folder holds the default (m2=1) and `_noM2` (m2=0) runs:
                     our_t_cost_{tag}_{n}_{start}_{stop}.txt   (per-case T cost)
                     our_cx_cost_{tag}_{n}_{start}_{stop}.txt  (per-case CX cost)
                     our_results_{tag}_{n}_{start}_{stop}.txt  (per-run summary: avg synthesize
                     wall, Exorcism/SSHR comparison blocks, G-3 bound line computed on the fly)
    deg_bound/       historical G-3 lower bound t(deg f) files, kept for reference only;
                     evaluate.py no longer writes them (the bound is now computed in the
                     our_results report)

                     separate supplementary timing probes (not a synthesis route)
    no_M2_vs_default.txt   (per-case M2-vs-noM2 comparison, generated by compare_no_m2.py)

                     from the per-path folders)
```

## Naming rules

- `path` (the evaluate.py argument) is the base route and folder name; it is one of:
  - `A`    BDD path
  - `A0`   preprocessed DD cover, fusion engine and circuit segment reordering off
  - `F`    ANF path
  - `F0`   raw ANF cover, fusion engine off
  - `FS`    FPRM path with shift search (the production default)
  - `FP`   FPRM path with the proxy prescreen
  - `FG`    GL(n,2) local search
  - `MT`   minterm-cover start + fusion engine
  - `MT0`  minterm-cover raw emission, fusion engine off
  - `PK`   pseudo-Kronecker cover + fusion engine
  - `PKS`  PK cover with shift search
  - `PKP`  PK cover with the proxy prescreen
  - `PK0`  PK cover raw emission, fusion engine off
- `n` is the number of variables; `start`/`stop` are the case range taken from
  `test_cases_{n}` (inclusive start, exclusive stop).
- Default runs are produced with the macro-M2 post-processing **on** (`m2=1`, plain tag);
  comparison runs with it **off** (`m2=0`) carry the `_noM2` tag suffix and live in the
  same per-path folder.
- `A0`, `F0`, `MT0`, and `PK0` ignore `m2`, always use their plain tag, and skip fusion,
  macro moves, and circuit segment reordering. All four retain basic circuit simplification.
  A0 also retains A's complete DD preprocessing and the extracted root-mask transformations.
- Evaluation uses zero ancillas and verifies every circuit against its truth table.
  Verification and Qiskit conversion are excluded from `avg synthesize wall`.
- Paper runtime entries use the arithmetic mean over the entire matching input
  interval: sum of per-case synthesis wall times divided by the number of cases.
  For the 1000-case comparisons, use the `avg synthesize wall` value in the exact
  `_0_1000` result file. Repeated timings of a sampled subset do not replace it.
- The G-3 lower bound `t(deg f)` depends only on `(n, tt)`; evaluate.py computes it on the
  fly in the `our_results` report. The old per-n files in `deg_bound/` are historical only.
- `reorder` (default 1) controls DD variable reordering in A and A0. It does not control
  circuit segment reordering, which is always disabled in A0.

The manuscript calls the X-map DD configuration **DD**; it corresponds to route
`A` in the implementation. Its data remain under `our_cost/A/`, with `A` in the
filenames and report labels. This is a paper-only name: `DD` is not a CLI alias.
The DD front end includes variable reordering, complemented-edge splitting
(`split_neg`), and local pattern-based splitting (`perform_split` / `split_with_pattern`).

The manuscript's **DD0** denotes raw emission of the same preprocessed DD cover,
with pairwise fusion, M2, and segment reordering disabled. It is distinct from
`A_noM2`, which retains pairwise fusion. DD0 corresponds to implementation route
`A0`, with data under `our_cost/A0/`; `DD0` is not a CLI alias. The A0-to-A CX
reduction includes the effects of both fusion and circuit segment reordering.

The manuscript's pairwise-only configurations **MT-**, **PK-**, **F-**, and
**DD-** correspond to `MT_noM2`, `PK_noM2`, `F_noM2`, and `A_noM2`, respectively.
They retain pairwise fusion and circuit segment reordering while disabling M2.
DD- also retains the same variable reordering and branch-splitting operations as
DD0 and DD. The three-stage comparisons therefore use MT0/MT_noM2/MT,
PK0/PK_noM2/PK, F0/F_noM2/F, and A0/A_noM2/A on identical input intervals.

## Route-name migration (2026-09-18)

The code, result directories, filenames, report labels, and manuscript now use:

- former `C0` -> `F0`: raw ANF;
- former `C` -> `F`: ANF + fusion, without shift search;
- former `F` -> `FS`: ANF + shift search + fusion (the production default);
- former `G` -> `FG`: ANF + shift search + local linear search + fusion.

`A`, `FP`, `MT`, `MT0`, `PK`, `PK0`, `PKS`, and `PKP` retain their names.
The `_noM2` suffix is unchanged: for example, former `F_noM2` is now `FS_noM2`,
stored in `our_cost/FS/`. The paper may abbreviate this configuration as `FS-`.
Numeric costs, case ordering, and recorded runtimes are preserved; this migration
does not represent a new measurement or an algorithm change.

Old route names are not accepted as aliases. In particular, `F` now means unshifted
ANF, so old commands using `F` for shift search must be changed to `FS`. In the
Python API, use `paths=('F',)` for unshifted ANF and `paths=('FS',)` for shift search;
the existing `fprm_proxy` and `gl_search` switches still select FP and FG.

Git history and archived exploratory notes/logs may retain the former names.
The retained local paired-M2 timing report is relabeled FS, with a naming note;
its original source hash and timestamps still identify the code used for that run,
and its numeric run log is unchanged. Development-stage identifiers such as `G-2.1`,
`G-2.2`, and `G-3` are historical task identifiers, not route names.

## Full-batch synthesis times

For the starting-cover and fusion-ablation comparisons, costs and runtimes
refer to the same complete 1000-function batches. The runtime is
`avg synthesize wall` from the matching result file. It describes mean synthesis
latency over the test workload and supports comparisons of practical time scales.
Each function contributes once; sampled or repeated timing probes are kept
separate from this reporting convention.

The six MT_noM2 and PK_noM2 batches at n=9,10,11 were rerun sequentially on
2026-09-26 through the unmodified `evaluate.evaluate_all(n, 0, 1000, route,
m2_post=False, reorder=True)` workflow. Only one batch/worker ran at a time.
There was no sampling, repeated trial, explicit pre-run garbage collection,
or excluded warm-up function. The environment is the same as documented above.
All 6000 circuits passed truth-table verification, and every T/CX record matched
the saved costs. Only the six canonical result reports were replaced; the
previous concurrent reports were archived before the reruns.

`our_cost/fusion_timing/fusion_full_batch_20260926.txt` records the protocol,
environment, source/input hashes, completion status, and old/new mean times.
Canonical result files keep the normal `evaluate.py` output format. Reproduce
one complete batch using, for example, `python evaluate.py 11 0 1000 MT 0` or
`python evaluate.py 11 0 1000 PK 0`. Run the commands sequentially when collecting
comparable full-batch timings.

## Supplementary timing probes

On 2026-09-26, `experiments/fusion_stage_timing.py` measured the raw, pairwise-only,
and full-engine configurations of MT, PK, F, and A (paper DD) for every n=5..11.
It uses the same hardware and software environment described above. The outputs
are retained in `data/our_cost/fusion_timing/`:

- `fusion_stage_timing_20260926.txt`: protocol, environment, input/source hashes,
  completion status, mean times, M2 time changes, and changes in each repetition.
- `fusion_stage_timing_20260926_runs.txt`: per-run wall/CPU nanoseconds, route,
  size, input index and truth table, repetition, execution position, stage, and
  verified T/CX costs. Repetition 0 identifies excluded warm-up runs.
- `m2_paired_timing_probe.txt` and `m2_paired_timing_probe_runs.txt`: unchanged
  copies of the earlier FS paired experiment from `experiments/phase0_results/`,
  retained here alongside the new timing evidence. These are earlier measurements,
  not reruns on 2026-09-26.

The new experiment uses indices 0,50,...,950 of the first 1000-function batch:
20 functions per size, two per original sampling interval. Each configuration
runs three times per function, sequentially in one worker. Each stage occupies
all three execution positions for each function; pairwise/full precedence is
balanced overall, and function order rotates between repetitions. Every run
uses a fresh synthesizer and complete production synthesis, without sharing
pools or search results. Constructor setup, pre-run garbage collection, circuit
verification, Qiskit conversion, cost counting, and I/O are outside the timer;
normal garbage collection remains enabled during synthesis. Index 1 warms up
each configuration once per size and is excluded from summary means.

All 5124 circuits (5040 measured runs and 84 warm-up runs) passed truth-table
verification and matched both saved T and CX costs exactly. The summary averages
60 measured runs per configuration and size. M2 time change is
`100 * (mean_full / mean_pairwise - 1)`, using unrounded durations; it is not an
average of per-function percentage changes. Its size varies with the cover,
so the earlier roughly 1%--2.5% paired FS increases must not be generalized to
all generators.

These 20-function timing probes are retained as supplementary evidence. They
are not the runtime source for the paper's tables: those use the complete
1000-function result-file means, as described above. In particular, the sampled
M2 percentage changes must not be substituted for full-batch synthesis times.
The earlier paired FS experiment is likewise retained in this directory for
reference. Any future use of the supplementary FS/FP ablation table should take
its runtimes from the corresponding complete 1000-case batch reports.

Reproduce the serial experiment with a new output prefix (existing records are
never overwritten):

```bash
LIMBDD_FUSION_DEBUG=0 python experiments/fusion_stage_timing.py --prefix fusion_stage_timing_repeat
```

The retained FS protocol is reproduced by
`python experiments/m2_paired_timing_probe.py --prefix fs_paired_repeat`; that
script writes new records to `experiments/phase0_results/`.

## External-method comparisons in Results

Throughout Results, the SSHR baseline is SSHR-H, the heuristic variant;
SSHR-I (the ILP-based variant) was not evaluated. This variant identification
follows the experiment author's clarification. Existing SSHR filenames and
table headings retain the short name SSHR.

Section 5.5 uses F/FS/FG at n=3..7 and F/FS/FP at n=8..11. Costs are matched
by truth-table identity and order: exhaustive sets of 256 and 65536 functions
at n=3 and n=4; complete 10000-function sets at n=5..7; and the first 1000
functions at n=8..11. The paper displays mean costs per function and computes
percentage reductions from unrounded aggregate costs on the same functions.
The additional F/FS per-function comparison table has two panels: Exorcism
(n=3..11) and SSHR (n=3..6), on the same corresponding function sets. For each
metric, the Lower, Same, and Higher columns explicitly give the percentages
with strictly lower, equal, and strictly higher cost than the named baseline.
Percentages are computed from exact counts and rounded independently to two
decimals, so the displayed values may not sum to exactly 100%.
These counts were checked against the result reports and the per-function cost
files. They do not represent joint improvement in both metrics.
Complete SSHR comparisons are available only at n=3..6. At n=7, the author
reports a preliminary evaluation of approximately 1000 functions with an average
runtime of roughly 4--6 minutes per function. The planned 10000-function run was
not completed because of the required runtime. This approximate pilot observation
is discussed separately in the paper; it is not a retained full-batch timing
record or a measured timeout. The aggregate table retains unavailable SSHR entries at n=7; the
SSHR per-function panel ends at n=6.

All timing means in the table correspond to these same complete input sets. For ACF,
use the result file with the exact case interval, including `_0_10000` at n=5..7.
The paper uses the arithmetic mean of the two unrounded Exorcism timing means
in each matching report. The T-cost and CNOT-cost interfaces use the same native
synthesis backend but return different metrics; the original separate timing
records are preserved. `exorcism_cost.py` calls and times these interfaces
separately.
Those timers cover the binding call and exclude truth-table packing and I/O;
ACF's reported wall time follows its own synthesis interface described above.
These are implementation runtimes, rather than measurements of intrinsic
algorithmic complexity under a common implementation.

The existing Exorcism summaries at n=8,9,10 describe 10000-function runs. To
supply the exact 1000-function comparison, those sizes were rerun sequentially
on 2026-09-26 through the unmodified `data/exorcism_cost.py n 0 1000`, using
the existing native binding and the same local WSL2/Python environment as ACF.
Each function was evaluated once for each metric. All 6000 resulting T/CX
records exactly matched the corresponding prefixes of the original baseline
files. The original costs and 10000-case timing reports remain unchanged;
`exorcism_time_{n}_0_1000.txt` contains the new standard timing output, and
`matched_timing_20260926.txt` records the protocol, hashes, environment, means,
and validation. At other sizes, the existing baseline time reports already
match the comparison sets. New timing runs should use an isolated output
directory because the original evaluation script writes fixed filenames.

## Reproducing a run

```bash
python evaluate.py <n> <start> <stop> <path> [m2] [reorder] [--output-dir DIR] [--overwrite]
#  path is one of A A0 F F0 FS FP FG MT MT0 PK PK0 PKP PKS; m2=0 produces the _noM2 comparison runs
#  (default m2=1, ignored for raw routes); reorder (default 1) affects DD variables in A/A0
```

Run from the repository root. The default output root is `data/our_cost`; for a
reproduction run, use `--output-dir runs/reproduction` to retain the paper results.
Each route still gets its own subdirectory. The evaluator rejects existing batch
files unless `--overwrite` is explicitly supplied, and publishes results only after
every circuit in the batch has been verified. It rejects invalid input intervals
and checks baseline truth-table keys before comparing costs. Missing, empty, or
shorter baselines are skipped; mismatched or malformed records are errors.

The added pairwise-only MT and PK costs can be reproduced with the existing
M2 switch, for example:

```bash
python evaluate.py 11 0 1000 MT 0 --output-dir runs/reproduction
python evaluate.py 11 0 1000 PK 0 --output-dir runs/reproduction
```

These commands use the same sequential full-batch procedure as the refreshed
result reports. Results use `MT_noM2`/`PK_noM2` filenames in the
`MT`/`PK` subdirectories of the selected output root.

The preprocessed DD baseline uses `data/our_cost/A0/our_{t,cx}_cost_A0_{n}_0_1000.txt`
and `our_results_A0_{n}_0_1000.txt`. Reproduce one group with
`python evaluate.py 8 0 1000 A0 1 1 --output-dir runs/reproduction`: DD variable reordering is enabled, while fusion,
M2, and circuit segment reordering are disabled. The `m2` argument is ignored for A0.

Raw ANF results use `data/our_cost/F0/our_{t,cx}_cost_F0_{n}_0_1000.txt` for
`n=5..11`, matching the starting-cover comparison subsets. Reproduce one group with
`python evaluate.py 8 0 1000 F0 --output-dir runs/reproduction`. These F0 measurements were collected on 2026-09-17
with an AMD Ryzen 9 7945HX, WSL2 Linux 6.6.87.2, Python 3.12.3, NumPy 2.5.2,
Qiskit 2.5.2, and SciPy 1.18.0. Groups ran sequentially; the reported time includes
synthesis only, excluding circuit verification, Qiskit conversion, and file I/O.
The committed code, input cases, per-case costs, and TXT summaries identify the experiment;
no separate metadata JSON is required. Older routes were measured in earlier runs, so
runtime comparisons are descriptive rather than a controlled timing experiment.

`python -m experiments.data_summary` summarizes the largest saved batch per route and prints
its input interval. Compare route totals only on identical intervals (the cover comparison
uses `[0,1000)` for n=5..11). Each Exorcism reduction uses that route's own interval.

For paper figures, `python -m experiments.plot_results` instead requires the exact
requested interval, checks every truth-table key, and exports T/CX totals plus the
corresponding report's mean wall time to `figure/results/starting_cover_summary.csv`.
It generates a two-panel T-cost figure for the eight optimized routes: absolute
totals and totals normalized to F at the same n. Use `--metric cx` for the same CX
layout, or `--metric time` for the same eight optimized routes' mean synthesis times on a linear axis
(ms/function). The figures display A0/A as DD0/DD; CSVs preserve source route names
and provide display labels. DD is included in the cost and time figures. The raw baselines
MT0, PK0, F0, and DD0 are reserved for separate comparisons and are omitted from the
default time figures; `--routes` can select them explicitly. Raw-cover totals, runtimes,
and per-size fusion reductions remain available in
the generated CSV files; old ten-route T-cost overview figures are not retained.
Install the optional
dependencies from `requirements-plot.txt`; generated artifacts stay under the
already ignored `figure/` directory.

## Comparing M2 vs no-M2

```bash
python data/compare_no_m2.py
#  emits data/our_cost/no_M2_vs_default.txt: per-case lower/higher/same counts,
#  percentages and total costs of the default (M2-on) runs against the _noM2 runs,
#  matched by the `tt` key. Both variants are read from the per-path folders.
```
